1Entrypoint

Everything starts at main() in genscript_order_uploader.py (the shell wrapper just updates, activates the env, and runs it):

# genscript_order_uploader.py  (abbreviated)
if __name__ == "__main__":
    sys.exit(main())

def main() -> int:
    load_dotenv()
    args = parse_args()                         # --csv, --env test, --location, --batch-size

    df           = read_csv(Path(args.csv))      ┐ parse + validate
    tubes_by_row = build_tubes(df)               │ (no network — exits
    validate_tubes(tubes_by_row)                  ┘ here on bad data)

    benchling         = connect(args.env)        ┐ connect + look up ids
    registry_id       = benchling.registry...          │
    container_type_id = resolve_dropdown(...)     ┘

    return upload(benchling, df, tubes_by_row, ...)   # the five phases →

So the whole run is: parse & validate locally → connect → hand off to upload(), which does all the writing.

4The upload() loop

Each phase builds its payloads locally (no network), then pushes them. Bulk creates and transfers go in ≤100-item chunks; boxes are created one at a time.

#Build — genscript_parsePush — genscript_upload → SDK
1build_sequence_payloadsrun_bulk → aa_sequences.bulk_create
2build_lot_payloadsrun_bulk → custom_entities.bulk_create
3build_box_payloadscreate_boxes → boxes.create (per box)
4build_container_payloadsrun_bulk → containers.bulk_create
5build_transfer_requestsrun_bulk → containers.transfer_into_containers

Later phases consume earlier ids — and those ids don't exist anywhere until a push returns them. How each one is minted and handed forward:

Minted on push, fed to the next build

upload() alternates build → push five times, and later builds consume ids minted by earlier pushes:

  1. Sequences — build_sequence_payloads(df, registry_id) builds locally (pure); the push creates the entities in Benchling and their new ids are harvested into sequence_ids.
  2. Lots — sequence_ids is passed as a plain argument into build_lot_payloads(...), so each lot links exactly its own sequences; the push yields lot_ids.
  3. Boxes — built from local data alone (no minted ids needed); create_boxes pushes them one at a time and returns box_id_by_key.
  4. Containers — build_container_payloads(...) uses box_id_by_key to place each tube (parent_storage_id = "{box_id}:{pos}"); the push yields container_ids.
  5. Transfers — build_transfer_requests(...) pairs lot_ids with container_ids; the final push creates the transfers and returns nothing — the chain ends.

The only ids that exist before the run are the looked-up ones — registry_id and container_type_id, fetched read-only by main() at connect time.

  • Ids cross the parse/push boundary only as function arguments — the parser never talks to Benchling, so it stays pure even though the run alternates build ↔ push.
  • If phase n fails, everything from phases 1…n−1 already exists in the tenant with real ids; stage names the failing phase and cleanup undoes it by order id (§9). Per-row slicing of the flat id lists (seq_offsets, box_key) is the parser-side detail in §5d.

5Inside the parser — genscript_parse.py

Pure functions: CSV → Benchling payloads, no network. (Its one benchling_io import is just the log helper.) Five stages:

a · Reading the CSV — read_csv

Reads text-ish columns as strings (so ids, leading zeros, and |/,-delimited values survive), and fails fast on missing required columns.

df_head = pd.read_csv(path, nrows=0)                 # header only
text_cols = [c for c in _TEXT_COLS if c in df_head.columns]   # text-typed, present
df = pd.read_csv(path, dtype={c: str for c in text_cols})
missing = [c for c in REQUIRED_CSV_COLUMNS if c not in df.columns]   # → sys.exit
for col in text_cols: df[col] = df[col].fillna("").astype(str).str.strip()

b · Exploding a row into tubes — build_tubes

The four per-tube columns are |-delimited and column-parallel: the k-th slice of each describes tube k. Guards reject ragged rows; overrides fix known bad source data; positions are normalised.

boxes = split_pipe(row["Box Name"]); types = split_pipe(row["Box Type"])
poss  = split_pipe(row["Position"]); vols  = split_pipe(row["Volume(ml)"])
if len({len(boxes), len(types), len(poss), len(vols)}) != 1:
    sys.exit("… per-tube columns have unequal lengths")   # ragged guard
for k in range(len(boxes)):
    btype = BOX_TYPE_OVERRIDES.get(boxes[k], types[k])   # "Box 23/23" → 9x9
    tubes.append({"box": boxes[k], "btype": btype,
                  "pos": normalize_pos(poss[k]),        # lowercase, J→i
                  "vol": vols[k], "merge": row["Merge Date"]})

"B1 | B1 | B2" + "A1 | A2 | C8" → three tube dicts. normalize_pos rewrites J→i because GenScript labels a 9×9's 9th row "J" (skipping "I").

c · The validation gate — validate_tubes

Runs after build_tubes, before any network call. It rejects structurally impossible data so nothing half-writes:

  • every box type resolves to a schema (9x9 / 2x5)
  • a box name maps to only one type
  • every position is inside its box's grid (row letters skip I)
  • no two tubes claim the same (box, type, merge, position)

Any failure → sys.exit("[LOCAL_PARSE] ERROR …") listing every problem at once.

d · Building payloads & threading ids

Each build_*_payloads returns SDK model objects. The catch: later phases need ids that don't exist until earlier phases are pushed. The orchestrator threads them back in (the full mint-and-hand-forward chain is in §4); the parser-side slicing:

sequences→ ids → lots; boxes→ ids → containers; lots + containers→ transfers
  • Sequences → Lots: the flat sequence_ids list is sliced back per row by seq_offsets / row_seq_ids (padded to 4 with None), so each lot links exactly its own sequences.
  • Boxes → Containers: build_box_payloads dedups boxes by box_key = (box, type, merge); the returned box_id_by_key lets each container resolve its parent_storage_id = f"{box_id}:{pos}".
  • Lots + Containers → Transfers: build_transfer_requests pairs lot_ids[i] (source) with container_ids[j] (destination), carrying the per-tube volume and the lot's concentration.

e · Field mapping — lot_fields_for + make_fields

How one Lot's fields are assembled. The CSV headers don't match the Benchling field names, so a single LOT_FIELDS table is the source of truth for that translation:

# one table — (CSV column, Benchling field, transform, required?), 29 rows
LOT_FIELDS = [
    ("Concentration(mg/ml)", "Concentration (mg/mL)", to_float,      True),   # QC → required
    ("Buffer",               "Buffer",                empty_to_none, True),
    ("target1",              "Target1",               empty_to_none, False),  # metadata → optional
    ("no_of_seqs",           "Number of sequences",   to_float,      False),
    # … 25 more …
]

def lot_fields_for(row, seq_ids, tubes):
    out = {bench: tx(row[csv]) for csv, bench, tx, _ in LOT_FIELDS if csv in row.index}
    out.update(LOT_CONSTANT_FIELDS)                  # Supplier = "Genscript"
    out["Number of units"] = float(len(tubes))       # derived
    out["Volume (mL)"]     = round(sum(tube vols), 4) # derived
    for i, sid in enumerate(seq_ids, 1): out[f"Sequence{i}"] = sid
    return out
  • LOT_FIELDS — every scalar Lot field in one place: CSV column, Benchling field name, a text/number transform, and whether it's required (identity + QC) or optional (metadata). REQUIRED_CSV_COLUMNS is derived from that flag and checked in read_csv. Adding a field is one line here (plus creating it on the schema).
  • if csv in row.index skips columns absent from an order, so an optional one (e.g. target2 on a monospecific order) is simply not sent — no error.
  • make_fields then drops any None, so empty cells aren't sent either.
Note: a field only lands if the Benchling schema defines it — Benchling rejects writes to unknown fields, so LOT_FIELDS and the schema must stay in sync.

6Inside the pusher — genscript_upload.py

The only module that writes to Benchling. Nearly every write goes through one engine.

a · The bulk engine — run_bulk

Given a list of payloads, a submit callable, and an optional extract callable, it chunks, fires the async task, waits, checks, and collects ids:

chunk ≤100→ submit()→ wait_for_task→ check SUCCEEDED→ extract rows 
for chunk in chunked(items, chunk_size):               # ≤100 per request
    task = wait_for_task(benchling, submit(chunk).task_id)  # async → poll
    if task.status != AsyncTaskStatus.SUCCEEDED:
        raise RuntimeError(f"{label} chunk failed …")
    if extract is not None:
        rows = extract(task.response or {})
        if len(rows) != len(chunk):                    # length sanity check
            raise RuntimeError(f"{label} returned {len(rows)} for {len(chunk)}")
        results.extend(rows)

submit/extract are passed in per phase (e.g. aa_sequences.bulk_create + an extractor for the aaSequences rows). Transfers pass no extract and return nothing.

b · Boxes, one at a time — create_boxes

Benchling's boxes.create isn't a bulk endpoint, so boxes are the exception to run_bulk — created individually in a loop, returning {box_key: box_id} for the container phase to consume.

for key, payload in box_payloads:            # [(box_key, BoxCreate)]
    box = benchling.boxes.create(payload)
    out[key] = box.id
return out                                   # {(box,type,merge): box_id}

c · Resolving a dropdown — resolve_dropdown

Dropdown values need the option's id, not its name. Resolves "Container Type" → "Eppendorf" to an id once at startup.

d · Reading results — entity_field

Bulk responses come back as dicts or objects; entity_field(e, "id") reads the field either way.

7Inside shared helpers — benchling_io.py

Network plumbing (connect, wait_for_task — pusher only) plus two pure helpers (chunked, log). log is the parser's only reason to touch this file.

a · connect — the client, with a long timeout

Builds the client from .env, with a 120 s read timeout (the 5 s default is too short for task polls); the SDK's 429/5xx retry still applies.

client = httpx.Client(timeout=httpx.Timeout(120.0, connect=10.0))
return Benchling(url=url, auth_method=ApiKeyAuth(key), httpx_client=client)

b · wait_for_task — poll until done, retry blips

Bulk ops are async: submit returns a task_id, this polls it — retrying transient timeouts (NET_ERRS), up to 30 min, then raising TimeoutError.

while time.time() - start < max_wait_seconds:       # up to 1800s
    try:
        task = benchling.tasks.get_by_id(task_id)
        if task.status != AsyncTaskStatus.RUNNING:
            return task
    except NET_ERRS as e:                          # transient timeouts → retry
        print(f"(task poll retry: {type(e).__name__})")
    time.sleep(poll_interval)                        # every 2s

c · chunked & log

chunked(seq, n) yields n-sized slices (the ≤100 batching); log(label, msg) prints a timestamped HH:MM:SS [LABEL] line.

9Recovery

No result file — the tenant is the record, and progress is logged to the console (stage tags the failing phase). If a run dies partway, undo it by order id:

python dev-tools/cleanup_run.py --order-id U0000AAAA0 --env test

Cleanup finds everything by the order-id prefix in the names; sequences also via their lots' links and an Order ID-field scan — the scan is what catches sequences orphaned when phase 2 fails (no lot links them).

10Second entrypoint — cleanup

dev-tools/cleanup_run.py reverses a push by --order-id: archives containers + boxes, renames + archives lots + sequences. It reuses the uploader's SCHEMAS and benchling_io, so the two never drift. Usage: commands.md.
